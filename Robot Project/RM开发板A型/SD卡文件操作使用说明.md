# 第二阶段：SD 卡文件操作封装

本层为 `User/sd_storage.c` 和 `User/sd_storage.h`，Keil 分组为 `Application/User/Storage`。业务代码只需包含 `sd_storage.h`，不需要自己创建 FatFs 文件对象。

## 使用约定

- 一个 SD 卡文件系统，同一时刻只打开一个文件。所有文件操作由同一个前台执行流程调用。
- 第一阶段的系统时钟、GPIO 和驱动注册仍由原启动流程完成；本层不改动电机、串口和调零逻辑。
- 不在中断、关闭中断或屏蔽系统节拍的上下文调用这些函数；写入内存的两个接口同样不提供中断并发保护。
- 32GB 卡采用 FAT32，本层不格式化卡。文件名只接受根目录下的英文 8.3 名称，例如 `RUN00001.CSV`，不要传入盘符或目录。
- 全部函数返回明确结果。不能只看“没有卡死”，就认为数据保存成功。

## 函数一览

| 函数 | 作用 |
| --- | --- |
| `SD_Card_Prepare_For_Use()` | 准备驱动并立即挂载，确认文件系统可以使用 |
| `SD_Card_Finish_Using()` | 在文件已关闭后结束文件系统使用 |
| `SD_Card_Create_New_File(name)` | 创建新文件；重名时返回错误，不覆盖原文件 |
| `SD_Card_Open_File_To_Add_Data(name)` | 打开已有文件并移到末尾；文件不存在时报错 |
| `SD_Card_Open_File_To_Read_Data(name)` | 只读打开已有文件，从开头读取 |
| `SD_Card_Add_Data_To_Memory(data, length)` | 把一批原始字节完整复制进内存暂存区 |
| `SD_Card_Add_One_Line_To_Memory(text)` | 暂存一行 CSV 文本，自动补 `\r\n` |
| `SD_Card_Write_Memory_Data_To_File()` | 把暂存数据批量交给 FatFs，不强制同步所有文件信息 |
| `SD_Card_Save_All_Data_To_Card()` | 写完暂存数据，再完成文件数据及元数据同步 |
| `SD_Card_Save_And_Close_File()` | 写模式先保存再关闭；只读模式直接关闭 |
| `SD_Card_Read_File_Data(buffer, capacity, count)` | 分块读取，输出本次实际读到的字节数 |
| `SD_Card_Set_File_Read_Position(offset)` | 在只读模式下，设置下一次读取的字节位置 |
| `SD_Card_Get_Current_State(info)` | 查询当前状态、模式、文件大小、暂存量和最近错误 |
| `SD_Card_Give_Up_Unsaved_Data_And_Reset()` | 明确放弃未保存数据、清理文件会话并卸载，随后需重新准备和打开文件 |

## 三种“写入”动作的区别

### 先放内存

`Add_Data_To_Memory` 和 `Add_One_Line_To_Memory` 只复制数据，不进行 SDIO 传输。成功表示数据被模块完整接收，尚未确认保存到卡。

默认暂存区为静态 4096 字节，不使用动态内存。一批数据必须能完整放入当前剩余空间；空间不够就整批拒绝，调用方仍拥有完整原数据。单批超过 4096 字节属于输入过大，不能通过刷写重试解决，应由调用方分块。

单行接口的正文最多为 4094 字节，不带 `\r` 或 `\n`，函数自动添加两个换行字节。表头也是一行普通文本，由调用方在新建文件后加入；本层不固定传感器字段，不自动添加重复表头，不解释或转义 CSV 字段。

常用结果名称：

| 结果 | 调用方怎么处理 |
| --- | --- |
| `SD_CARD_OK` | 当前这一步成功；仍要按函数职责区分暂存、写文件和同步 |
| `SD_CARD_MEMORY_BUFFER_FULL` | 本批数据完全未接收；前台写出已有缓存，成功后重新提交本批 |
| `SD_CARD_DATA_TOO_LARGE` | 输入或文件长度超过允许范围，不能原样反复重试 |
| `SD_CARD_FILE_ALREADY_EXISTS` | 换一个新文件名，或明确选择打开旧文件追加 |
| `SD_CARD_FILE_NOT_FOUND` | 检查文件名；需要新建时明确调用创建接口 |
| `SD_CARD_NO_CARD` | 首次准备时无卡可插卡后重试；会话中拔卡则需检查故障状态 |
| `SD_CARD_PARTIAL_WRITE` | 未完整写出，停止继续采集到此文件并查询诊断，不重复提交整批 |
| `SD_CARD_NEED_RESET` | 之前的故障仍被锁存；查询原始原因，决定是否明确放弃未保存数据 |

下面仅说明“缓存满后重试原数据”的调用方法，`csv_line` 由未来业务代码生成；它不是已加入固件的测试程序：

```c
SD_Card_Result result;

result = SD_Card_Add_One_Line_To_Memory(csv_line);
if (result == SD_CARD_MEMORY_BUFFER_FULL)
{
    result = SD_Card_Write_Memory_Data_To_File();
    if (result == SD_CARD_OK)
    {
        result = SD_Card_Add_One_Line_To_Memory(csv_line);
    }
}
/* 必须继续检查 result；只有 OK 才表示这一行已被完整接收。 */
```

### 批量交给文件

前台在合适时机调用 `Write_Memory_Data_To_File`。若暂存区已满，可以先调用它，成功后再提交原先被拒绝的整批数据。

该函数同步执行文件写入，期间会等待 SD 卡。它没有创建后台线程，也没有让主循环在写卡期间继续运行。成功后，数据已交给 FatFs；部分数据或文件信息仍可能在文件系统缓存中。

### 完成同步保存

`Save_All_Data_To_Card` 先写出模块内的数据，再调用文件系统同步操作。`Save_And_Close_File` 在写模式下先完成保存，再关闭文件。每步均检查返回结果。

同步成功表示 FatFs 和当前卡驱动已报告操作完成；不能将它解释成任何断电条件下都不会丢数据的物理保证。本阶段不设置每条记录同步或固定定时同步策略。

## 推荐调用顺序

创建新的采集文件：

1. `Prepare_For_Use`。
2. `Create_New_File("RUN00001.CSV")`。
3. 用 `Add_One_Line_To_Memory` 加入一次表头。
4. 连续加入数据行，前台按批次调用 `Write_Memory_Data_To_File`。
5. 在需要的保存点调用 `Save_All_Data_To_Card`。
6. 采集结束调用 `Save_And_Close_File`。

继续向旧文件末尾添加数据时，第 2 步改为 `Open_File_To_Add_Data`，不重复加入表头。切换文件之前必须先关闭当前文件。

准备读取文件并发送：

1. 准备好文件系统，确认写入文件已正常关闭。
2. `Open_File_To_Read_Data`。
3. 反复 `Read_File_Data`，每次只处理实际读取的字节数。
4. 成功且实际读取为 0 表示文件结束，不属于错误。
5. 需要重新读取某段时用 `Set_File_Read_Position`；位置从 0 开始，不能超出文件长度。
6. `Save_And_Close_File` 关闭只读文件；无需继续使用卡时 `Finish_Using`。

读取接口不自动补字符串结尾的 `\0`。无线发送时应使用实际长度；如果要临时当 C 字符串显示，需要调用方预留额外空间并自行补结束符。

## 出错后怎样处理

参数不合法、暂存区满、输入过大、文件不存在和新建重名等错误不直接破坏当前文件会话。根据具体结果调整参数或操作顺序。

真正的读写、同步、关闭错误，以及只写入部分数据的情况，会进入故障状态。模块停止接受后续文件操作，并保留原故障信息；可以用 `Get_Current_State` 查询。写入完成的前缀按实际返回长度移出暂存区，未完成尾部保留统计，不自动重复发送到文件。

此时不能简单重新提交同一批数据，也不能把旧内存内容自动写入另一张卡。调用方确认放弃当前未保存内容后，调用 `Give_Up_Unsaved_Data_And_Reset`，再重新准备文件系统、重新打开文件。该函数是显式放弃操作，不是“保证先保存”的快捷恢复。

文件大小是当前文件对象记录的逻辑长度，不等于已经同步到卡上目录项的长度；暂存区字节数单独报告。普通文件不存在等错误和磁盘错误也分别报告，底层 FatFs 结果仅作为诊断依据。

## 1.5 ms 采样与阶段边界

约每秒 667 条数据的目标需要测量真实每行长度、SD 卡吞吐量、最长写入停顿以及缓存占用。4KiB 是批量写缓冲，不是覆盖任意卡停顿的采集队列，也不代表已满足持续采集目标。

第二阶段只实现文件封装及软件验证，不把这些调用插进现有 PID 主循环或接收中断。第三阶段再加入上板测试程序；正式运动采集需要的调度和中断数据队列另行设计。
