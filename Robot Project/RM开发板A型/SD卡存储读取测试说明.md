# 第三阶段：没有传感器时的 SD 卡上板测试

## 方法

由 STM32 自行生成一组确定的 CSV 内容，写入板载 SD 卡，然后关闭文件、重新打开、逐字节读回比较。模拟内容可以从序号重新算出来，因此无需传感器，也无需用另一个大数组保存期望文件。

测试只使用第二阶段的文件接口，不涉及无线协议、真实测距或真实电机反馈。

## 测试数据

默认生成 20,000 条数据，CSV 表头为：

```csv
seq,time_us,laser_um,motor_angle_mrad
```

第 `seq` 条数据的规则：

| 字段 | 规则 | 含义 |
| --- | --- | --- |
| `seq` | 0 到 19999 | 模拟样本编号 |
| `time_us` | `seq * 1500` | 按 1.5ms 间隔计算的虚拟采样时间，单位微秒 |
| `laser_um` | `100000 + seq % 1000` | 模拟激光测距值，单位微米 |
| `motor_angle_mrad` | `seq * 5` | 模拟累计角度，单位毫弧度 |

例如前两条为 `0,0,100000,0` 和 `1,1500,100001,5`。这些数字完全由程序生成，不代表真实管径、真实电机转角或现场测量结果。

时间列是模拟数据，不是程序每 1.5ms 实际生成一条的证明。当前连续生成并批量写入，用于测量总体吞吐量，不执行真实定时中断采集。

## 自动执行的检查

1. 准备并挂载文件系统。
2. 在 `ST000001.CSV` 到 `ST001000.CSV` 范围内寻找可新建的文件名。遇到已有文件就跳过，不覆盖、不删除、不格式化；全部占用则明确失败。
3. 写入表头和前 10,000 条数据。缓存满时先批量写出，再重试原来的整行；每 1,000 条进行一次同步保存。
4. 保存并关闭文件，再打开同一个文件追加后 10,000 条，不重复表头，最后保存关闭。
5. 检查读取位置功能，再以 512 字节为一块读完整个文件，和重新生成的内容逐字节比较，检测错误、缺失、多余内容及 EOF。
6. 关闭并卸载，再重新挂载、重新读取并比较，确认没有依赖上一轮文件系统缓存。
7. 成功后正常关闭、卸载，保留 CSV，方便取出 SD 卡在电脑上查看。失败时停下并保留诊断，不自动丢弃数据或反复重写。

卸载重挂不等于断电重启，本测试不声称验证了掉电恢复能力。

## 如何运行

1. 将卡插在 A 板自带的 TF 卡槽中，确认使用 FAT32。本程序遇到无卡或不支持的文件系统会报告失败，不会自动格式化。
2. 打开机器人 `MDK-ARM/test_feedback.uvprojx`，不要打开官方 SDCard 示例。
3. 在 `User/sd_card_test.h` 中检查 `SD_CARD_TEST_MODE`。默认值为 **1**，表示独立 SD 卡测试；也可通过工程预定义宏覆盖。
4. 全部重新编译，然后下载到 A 板。使用 Keil 调试时，在 Watch 窗口添加 `g_SD_Card_Test_Result`，展开观察。
5. 连续运行到测试结束。计时过程中不要打断点或单步；否则测到的耗时包含人为调试影响，不能用于评价卡速度。
6. 每次上电只执行一次。无卡、卡格式错误或其他失败修正后，复位开发板重新测试。

独立测试模式只初始化测试必需的 GPIO、SDIO 和文件系统，PH2～PH5 保持关闭输出；不初始化 CAN、无线串口或电机控制。调零开关 EXTI0/1 不启用，SysTick 只保留系统节拍，不运行累计距离逻辑。测试结束后一直停留在显示结果的循环，成功或失败均不会进入机器人控制。

PG1 对应的板载 LED 为低电平点亮：测试通过后常亮；失败后按 500ms 间隔闪烁。文件测试执行期间不依赖 LED 动画显示进度，具体进度看 Watch 中的阶段字段。

在 Watch 中展开 `g_SD_Card_Test_Result`，重点看：

| 字段 | 怎么判断 |
| --- | --- |
| `status` | `SD_CARD_TEST_PASSED`（2）表示内容检查通过，`SD_CARD_TEST_FAILED`（3）表示失败 |
| `stage`、`test_error` | 当前进度或首次失败阶段、测试错误原因 |
| `filename` | 本次创建的文件名，取出卡后用它找到 CSV |
| `rows_written` | 完整接收的模拟数据行数，成功应为 20000，不含表头 |
| `bytes_written_expected`、`bytes_verified` | 预期文件大小及当前读取遍次已匹配字节数，成功应相等 |
| `completed_read_passes` | 成功应为 2，表示首次读回和重挂载读回都已完成 |
| `seek_check_passed`、`eof_verified` | 读取位置和文件结束检查是否通过 |
| `last_result`、`storage_info` | 存储接口结果及原始文件系统错误；应在失败时一起查看 |
| `first_mismatch_valid`、`first_mismatch_offset` | 是否发现内容长度或字节不匹配，以及首次不匹配位置 |
| `first_mismatch_expected`、`first_mismatch_actual` | 期望/实际字节；`0x100` 表示该侧已经没有更多字节 |
| `write_elapsed_ms`、`max_write_pause_ms` | 写入总耗时、写阶段单次存储调用最大停顿，单位毫秒 |
| `throughput_valid`、`rows_per_second`、`avg_meets_667hz` | 平均速度是否有有效计时、每秒行数及是否满足平均预算 |

`status` 通过与 `avg_meets_667hz` 达标是两个结论；程序不会把平均速度偏慢伪装成内容错误，也不会用速度达标代替内容检查。

## 怎样看待写入速度

程序统计从开始写表头到追加部分最终保存关闭的总时间，包含数据格式化、批量写入、周期同步、中途关闭和重新打开追加的时间，不包含读回校验。

20,000 条、每条 1.5ms 对应 30,000ms。实际写入总时间不超过这个值，说明本次独立测试的平均处理能力达到约 667 条/秒；若耗时为 0，毫秒计时分辨率不足，不能把结果当成可用的速率测量。

同时记录写阶段的最长存储调用停顿。一个较长的停顿即使不影响整体平均速率，也会要求真实采集端有足够的数据队列。因此：

- 文件比较通过，表示本次生成的数据被正确写入并读回。
- 平均速率满足目标，表示本次独立负载下总体处理能力满足该平均数据量。
- 两项都通过仍不等于真实 UART8 接收、CAN 反馈、电机 PID 与存储同时工作时不丢数据。那个结论需要后续联合测试。

本测试采用毫秒节拍统计，不能据此给出小于 1ms 的单次延迟精度。

## 恢复机器人正常运行

将 `SD_CARD_TEST_MODE` 改为 **0** 后重新编译、下载。原有机器人初始化、PID 主循环、调零中断及累计距离逻辑会按原路径编译。

仅在电脑上修改宏不会改变板上已经下载的固件。测试生成的 CSV 继续保留在卡上，不会因为切换模式而自动删除。
