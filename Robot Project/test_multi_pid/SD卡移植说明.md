# 第一阶段：SDIO / FatFs 基础层移植

本阶段按审批方案把官方 SDCard 工程的 SDIO、板级 SD 驱动和 FatFs R0.12c 移入机器人现有工程。上层 CSV 封装属于第二阶段，实卡写入、读回及性能测试属于第三阶段。

## 硬件与时钟

使用 A 板板载 TF 卡槽：PC8～PC11 为 D0～D3，PC12 为 CLK，PD2 为 CMD，PE15 为低有效机械插卡检测。PE15 配置内部上拉、普通输入，不开启插拔中断。SDIO 数据和命令脚使用 AF12；板载数据、命令线上已有外部上拉。

保留主频 180 MHz、APB1 45 MHz、APB2 90 MHz，仅将 PLLQ 从 4 改为 8：

```text
HSE 12 MHz / PLLM 6 * PLLN 180 = VCO 360 MHz
VCO / PLLP 2 = SYSCLK 180 MHz
VCO / PLLQ 8 = SDIO 源时钟 45 MHz
卡初始化：45 MHz / (118 + 2) = 375 kHz
正常传输：45 MHz / (0 + 2) = 22.5 MHz
```

不改变现有 CAN 波特率及串口总线时钟。当前方案不提供 USB 所需的精确 48 MHz，后续若启用 USB，需重新规划该时钟域。

本阶段沿用轮询方式，不启用 SDIO 中断、不分配 SD DMA。UART8 的 PE0/PE1 与 SDIO 无重叠；E62 的 AUX、M0、M1 未连接 A 板 GPIO。UART8 后续若使用 DMA 接收，需要 DMA1 Stream6 Channel5，而现有 USART2 绘图发送使用同一 Stream6 的 Channel4，届时需实际解除 USART2 TX 的 DMA 配置并调整发送方式。本阶段不启用 UART8，也不改变 Serialplot。

## 初始化顺序及职责

`main()` 在原有外设初始化后调用：

1. `MX_SDIO_SD_Init()`：只准备 `hsd` 参数，不访问卡。
2. `MX_FATFS_Init()`：只注册 `SD_Driver` 并生成 `SDPath`，不挂载文件系统；`retSD == 0` 表示注册成功，不代表有卡或挂载成功。

后续上层显式挂载时，调用链才进入 `disk_initialize()` → `SD_initialize()` → `BSP_SD_Init()` → HAL 卡识别和 4 位总线切换。驱动注册成功后不应自行调用 `FATFS_UnLinkDriver()`；正常卸载应使用 FatFs 的卸载接口，保持驱动注册关系。

启动不格式化、不挂载、不打开或读写文件，无卡不会在新增启动流程中等待卡响应。官方 `MDK-ARM/app/sd_card.c/.h` 示例未移植，其中包含 `f_mkfs()` 和覆盖创建文件操作。

## 文件系统配置

- 支持 FAT12/FAT16/FAT32，本项目的 32GB 卡选用 FAT32；实卡当前格式尚未确认，exFAT 不受本配置支持。
- 读写启用、512 字节逻辑扇区、单卷、非重入访问。
- 使用英文 8.3 文件名，例如 `RUN00001.CSV`；关闭长文件名、快速定位表和字符串读写函数，不需要额外的名称转换源文件。
- 格式化功能关闭；挂载失败不得自动格式化卡。
- 不依赖 RTC，文件元数据日期固定为 2026-01-01。这个日期不是实际采样时间，采样时间应在后续 CSV 字段中单独保存。
- FatFs 的文件占用检查不等于线程互斥；文件系统由一个前台执行流程串行访问。
- 启动栈由 1 KiB 增至 4 KiB；堆保持 512 字节，未引入运行时动态内存分配。
- FAT32 单文件长度小于 4 GiB；后续封装可按采集批次或大小分文件。

## 对官方模板的必要修正

- `BSP_SD_IsDetected()` 读取 PE15，不再固定返回“有卡”；拔卡使卡初始化记录失效。
- 无卡、初始化失败、无效容量及传输失败向上返回错误，重新插卡后需重新初始化、重新挂载；旧文件句柄不能继续使用。
- 磁盘读写与等待卡就绪分别采用默认 2000 ms 的可配置软件超时，不使用 `SDMMC_DATATIMEOUT=0xFFFFFFFF` 作为毫秒等待参数。超时按无符号 tick 差值判断，可跨越 tick 回绕。
- `CTRL_SYNC` 等待卡就绪；读写、状态与同步均检查实际错误，避免无限空转。
- 修复通用 `diskio.c` 中初始化失败仍缓存为已初始化的问题，使无卡失败后能够再次初始化。
- 保留当前轮询所需的 BSP 接口；不提供未配置 DMA 的模板接口，避免误用空 DMA 句柄。
- 新增底层读写拒绝中断上下文调用。文件系统本身仍要求调用者遵守单一前台访问约定。

2000 ms 是单次 HAL 数据传输或卡就绪等待的配置值，并非一个 `f_write()` 调用的整体耗时上限；FatFs 可能进行多次扇区和元数据操作，HAL 内部命令还各有超时。它也不是采样周期保证。

## 1.5 ms 采样周期对后续阶段的约束

1.5 ms 约为每秒 667 次采样，需要区分“及时接收并保留样本”和“每条立即物理写入卡”。SD 卡存在内部编程及文件系统元数据更新延迟，不能据此移植承诺每条在 1.5 ms 内落盘。

后续方案应让接收中断保存接收时间、最近一次电机角度及必要状态并入队；前台从缓冲区批量生成和写入 CSV。缓冲区大小和同步间隔需通过第三阶段的持续吞吐量、最大写入停顿、错误数及队列峰值实测确定。收到无线数据时读到的是最近一次 CAN 反馈角度，时间对齐精度也应在最终采集设计中明确。

当前 PID 仍由主循环执行。轮询 SD/FatFs 会阻塞主循环，即便改成 DMA 后再同步等待，也不能自动解决控制周期问题。正式边运动边记录前需要另行审批控制调度和缓存方案。本次未修改 PID、CAN、串口业务或传感器协议。
